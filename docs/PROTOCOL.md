# 状态协议与实现

## 已验证接口

当前匹配的接收器为 USB `VID 0x3837`、`PID 0x600A`，实机版本号 `0x0021`。筛选 HID 用途 `0x0001`、用途页 `0xFF90`，输入/输出报文长均为 64 字节、无 Feature 报文，输入报文编号为 `0x55`。出现多个匹配接收器时返回错误，不任意选择其中一个。

状态查询为 64 字节输出报文：

```text
55 65 01 00 ... 00
```

有效响应以 `55 65` 开头，第三字节为电量（0～100），第四字节为状态。官方 HUB 的对应状态值包括：

| 十进制值 | 含义 | 当前程序处理 |
| --- | --- | --- |
| 2 | 放电 | 在线 |
| 3 | 充电 | 在线 |
| 4 | 充满 | 在线 |
| 26 | 休眠 | 离线 |

实机拿起并连接时收到 `55 65 64 02 ...`，表示电量 100%、放电。放回底座关机后，接收器仍能接受查询，但不再返回状态响应；连续三次等待均超时，判为离线。重新拿起连接后恢复有效响应。

参考 [迈从官方 HUB 查询代码](https://cdn.mchose.com.cn/customPage/prod/assets/hidDeviceOptions-Sp1r1Ins.js)。仓库只描述接口事实并包含独立实现，不再分发官方脚本。

## 检测与错误区分

托盘计时器每秒尝试安排一次后台检测，已有检测运行时不重叠执行。每次查询的回复等待上限约 1 秒，最多三次；非状态通知被忽略，但不延长该次总等待上限。

- 有效状态回复：在线，休眠状态码除外。
- 查询发送成功，但连续三次回复超时：离线。
- 接收器不存在：切到备用扬声器。
- 发送失败、权限或 HID 错误、报文长度/电量异常：错误，保留当前输出并重试。

读取使用原生重叠 I/O；取消后等待操作完成再释放缓冲区，避免异步访问已释放的内存。程序只发送状态查询，不发送配置或固件命令。

## Windows 输出切换

使用 Core Audio 读取三个默认输出：常规、媒体、通信。通过 `IPolicyConfig.SetDefaultEndpoint` 设置相应角色后重新读取核对；其中一步失败会尝试恢复已改变的角色。

`IPolicyConfig` 并非微软承诺稳定的公开设置接口，未来 Windows 版本可能改变行为。接口布局参考 [AudioDeviceCmdlets](https://github.com/frgnca/AudioDeviceCmdlets/blob/master/SOURCE/IPolicyConfig.cs)；读取默认设备参考 [微软 IMMDeviceEnumerator 文档](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdeviceenumerator-getdefaultaudioendpoint)。

保存设备编号，优先按编号查找；编号变化时，只有名称匹配到唯一活动设备才使用该设备，避免切到任意输出。目标输出不可用时保留现有声音设备并约每 5 秒重试。

只有需要应用另一种目标状态、首次启动、恢复自动切换或保存设置时才切换。在同一状态下，不持续覆盖用户手动选择的设备。
